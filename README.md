# RAG: поиск по локальным документам

Ассистент по PDF и TXT с Telegram-ботом, CLI и дополнительным интерфейсом Streamlit.
Поиск использует версионированный FAISS-индекс, генерация — Gemini. Ответы содержат
ссылки на страницы; проверенные банковские графики строятся локально из SQLite.

## Структура

```text
rag/                  модули поиска, истории, подтверждений, метрик и таблиц
scripts/              аудит корпуса и сравнение моделей
tests/                офлайн-тесты и fixtures контрольных вопросов
docs/reports/         обзор архитектуры и отчёты этапов реализации
data/                 локальные PDF/TXT (не публикуются)
reports/              локальные результаты проверок (не публикуются)
bot.py                Telegram
main.py               интерактивный CLI
app.py                Streamlit
build_index.py        подготовка текста и сборка индекса
build_tables.py       сборка проверенной числовой таблицы
run.ps1               вспомогательный Windows launcher
```

Индексы, подготовленные фрагменты, SQLite, виртуальные окружения и ключи остаются
локально. Папки с результатами создаются по мере работы.

## Установка

В корне проекта создайте виртуальное окружение и установите зависимости:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если PowerShell запрещает активацию, вызывайте `.venv\Scripts\python.exe` напрямую.
CI настроен на Python 3.12 для Windows и Linux. Локальные проверки выполнялись
на Python 3.14 с предупреждениями библиотек; GitHub Actions ещё не запускался.
Прямые зависимости зафиксированы, транзитивные разрешаются pip.

Скопируйте `.env.example` в `.env`, не перезаписывая существующий файл. Заполните:

- `GOOGLE_API_KEY` — для индекса и текстовых ответов;
- `TELEGRAM_BOT_TOKEN` — только для настоящего Telegram-бота;
- `TELEGRAM_ALLOWED_USER_IDS` — свой ID для личного бота (пусто означает открытый доступ);
- `RAG_MODEL` — модель генерации; по умолчанию `gemini-2.5-flash`.

## Проверка без ключей

```bash
python -m unittest discover -s tests -v
python bot.py --check
python scripts/compare_models.py
```

Последняя команда выводит расчётные сценарии, не вызывает модели. Тесты заменяют
сетевые вызовы локальными объектами. Два теста реальных банковских PDF пропускаются,
если локальный корпус отсутствует. Ключи не нужны для тестов.

## Документы и запуск

Положите документы в `data/my_docs/`:

```bash
python build_index.py --topic my_docs --prepare  # текст без API
python build_index.py --topic my_docs --build    # вызовы Google, нужен ключ
python main.py --topic my_docs
python bot.py
```

Интерфейсы загружают готовый индекс и не строят его автоматически. При изменении
документов или настроек индекса требуется повторный `--build`.

Для Streamlit:

```bash
python -m pip install -r requirements-ui.txt
python -m streamlit run app.py
```

Streamlit оставлен как дополнительный локальный интерфейс, не как многопользовательский
публичный сервис. Telegram запускайте одним polling-процессом.

## Проверенные графики и оценка

`python build_tables.py` проверяет исходный PDF РИА Рейтинг и создаёт SQLite.
Доступны активы пяти банков на две даты 2025 года. Этот PDF не включён в репозиторий;
без него графики недоступны. Другие таблицы не извлекаются автоматически.

```bash
python scripts/evaluate_rag.py --check
# После настройки ключа, банковского корпуса и рабочего индекса:
python scripts/evaluate_rag.py --run --model gemini-2.5-flash-lite --output reports/eval_lite.json
```

Контрольный набор относится к отдельному банковскому корпусу. Проверка ссылок
структурная и не гарантирует правильность каждого утверждения. Калибровка поиска,
облачное сравнение качества и задержек пока не выполнены. Подробности — в
[отчёте этапа 6](docs/reports/STAGE6_RU.md).

Отчёты этапов описывают историю реализации. Ссылки в них на машинные результаты
из `reports/` работают только в локальной папке с этими результатами; в GitHub они
не публикуются. Для текущих путей и команд используйте этот README.

## Публикация на GitHub

Перед первым коммитом проверьте `git status --short` и `git diff --cached`.
`.gitignore` исключает корпус, `.env`, индексы, логи и машинные отчёты; `.env.example`
остаётся в репозитории. Исходные документы не добавляйте через `git add -f`.
Если секрет уже попадал в историю Git, одного `.gitignore` недостаточно.

После проверки файлов создайте пустой репозиторий на GitHub, затем:

```bash
git add .
git commit -m "Prepare RAG project for GitHub"
git branch -M main
git remote add origin <URL-вашего-репозитория>
git push -u origin main
```

Лицензия для распространения кода пока не выбрана владельцем проекта.
