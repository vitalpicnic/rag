# RAG: поиск по локальным документам

Ассистент по PDF и TXT с Telegram-ботом, CLI и дополнительным интерфейсом Streamlit.
Поиск использует версионированный FAISS-индекс, генерация — Gemini. Ответы содержат
ссылки на страницы; проверенные банковские графики строятся локально из SQLite.

## Структура

```text
rag/                  модули поиска, истории, подтверждений, метрик и таблиц
scripts/              аудит корпуса и сравнение моделей
tests/                офлайн-тесты и fixtures контрольных вопросов
docs/reports/         обзор архитектуры и отчёты этапов реализации
data/                 локальные PDF/TXT (не публикуются)
reports/              локальные результаты проверок (не публикуются)
bot.py                Telegram
main.py               интерактивный CLI
app.py                Streamlit
build_index.py        подготовка текста и сборка индекса
build_tables.py       сборка проверенной числовой таблицы
run.ps1               вспомогательный Windows launcher
```

Индексы, подготовленные фрагменты, SQLite, виртуальные окружения и ключи остаются
локально. Папки с результатами создаются по мере работы.

## Установка

В корне проекта создайте виртуальное окружение и установите зависимости:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если PowerShell запрещает активацию, вызывайте `.venv\Scripts\python.exe` напрямую.
CI настроен на Python 3.12 для Windows и Linux. Локальные проверки выполнялись
на Python 3.14 с предупреждениями библиотек; GitHub Actions ещё не запускался.
Прямые зависимости зафиксированы, транзитивные разрешаются pip.

Скопируйте `.env.example` в `.env`, не перезаписывая существующий файл. Заполните:

- `GOOGLE_API_KEY` — для индекса и текстовых ответов;
- `TELEGRAM_BOT_TOKEN` — только для настоящего Telegram-бота;
- `TELEGRAM_ALLOWED_USER_IDS` — свой ID для личного бота (пусто означает открытый доступ);
- `RAG_MODEL` — модель генерации; по умолчанию `gemini-2.5-flash`.

## Проверка без ключей

```bash
python -m unittest discover -s tests -v
python bot.py --check
python scripts/compare_models.py
```

Последняя команда выводит расчётные сценарии, не вызывает модели. Тесты заменяют
сетевые вызовы локальными объектами. Два теста реальных банковских PDF пропускаются,
если локальный корпус отсутствует. Ключи не нужны для тестов.

## Документы и запуск

Положите документы в `data/my_docs/`:

```bash
python build_index.py --topic my_docs --prepare  # текст без API
python build_index.py --topic my_docs --build    # вызовы Google, нужен ключ
python main.py --topic my_docs
python bot.py
```

Интерфейсы загружают готовый индекс и не строят его автоматически. При изменении
документов или настроек индекса требуется повторный `--build`.

Для Streamlit:

```bash
python -m pip install -r requirements-ui.txt
python -m streamlit run app.py
```

Streamlit оставлен как дополнительный локальный интерфейс, не как многопользовательский
публичный сервис. Telegram запускайте одним polling-процессом.

## Проверенные графики и оценка

`python build_tables.py` проверяет исходный PDF РИА Рейтинг и создаёт SQLite.
Доступны активы пяти банков на две даты 2025 года. Этот PDF не включён в репозиторий;
без него графики недоступны. Другие таблицы не извлекаются автоматически.

```bash
python scripts/evaluate_rag.py --check
# После настройки ключа, банковского корпуса и рабочего индекса:
python scripts/evaluate_rag.py --run --model gemini-2.5-flash-lite --output reports/eval_lite.json
```

Контрольный набор относится к отдельному банковскому корпусу. Проверка ссылок
структурная и не гарантирует правильность каждого утверждения. Калибровка поиска,
облачное сравнение качества и задержек пока не выполнены. Подробности — в
[отчёте этапа 6](docs/reports/STAGE6_RU.md).

Отчёты этапов описывают историю реализации. Ссылки в них на машинные результаты
из `reports/` работают только в локальной папке с этими результатами; в GitHub они
не публикуются. Для текущих путей и команд используйте этот README.

## Аналитические режимы и экспорт PPTX

После обновления установите зависимости: `python -m pip install -r requirements.txt`
(для веб-интерфейса — `requirements-ui.txt`). Экспорт использует `python-pptx==1.0.2`.

- **Топ-менеджер банка** (`executive`): главный вывод, тенденции, взаимосвязи,
  возможное влияние на банк; факты отделяются от гипотез и сценариев.
- **Эксперт** (`expert`): подробный ответ, цифры, периоды, единицы, методики,
  сопоставление источников и ограничения.
- Режимы отличаются глубиной поиска, выбором контекста и бюджетом ответа.
  Старые «Текст», «Обзор» и банковские графики сохранены.

В Telegram выберите кнопку роли. Под ответом со ссылками появится
«Скачать слайд PPTX». Доступен последний ответ текущего пользователя и диалога;
очистка чата или смена роли/темы отключает старую кнопку. Это интерфейс
существующего бота: чтение каналов через техническую учётку не реализовано.

В Streamlit выберите режим в боковой панели, после ответа нажмите
«Подготовить слайд PPTX», затем «Скачать слайд PPTX».

```bash
python main.py --topic default --mode executive --pptx-dir reports/slides
python main.py --topic default --mode expert
```

PPTX содержит один редактируемый слайд с таблицей выдержек и ссылками.
Экспорт локальный, без повторного обращения к модели: числа копируются из ответа,
новые расчёты и графики не придумываются. Длинные фрагменты остаются полностью
в заметках; сокращение обозначается на слайде. В заметках сохранены вопрос,
полный ответ, источники и время формирования, которое не подменяет период данных.

### Приоритет официальной отчётности

Для каждой темы можно создать `data/<topic>/sources.json`. Ключ — путь PDF/TXT
относительно папки темы, с `/` для вложенных папок. Пример структуры
(замените SHA-256 и URL реальными значениями):

```json
{
  "bank_report.pdf": {
    "kind": "official_report",
    "sha256": "<64 символа SHA-256 файла в нижнем регистре>",
    "url": "https://bank.example/reports/2025.pdf",
    "title": "Годовая отчётность банка за 2025 год",
    "publisher": "Банк",
    "published_at": "2026-03-01"
  }
}
```

Получение хеша в PowerShell:

```powershell
(Get-FileHash -LiteralPath 'data/default/bank_report.pdf' -Algorithm SHA256).Hash.ToLowerInvariant()
```

`kind`: `official_report` — проверенная оператором официальная отчётность;
`analysis` — сторонняя аналитика; `unknown` — статус не установлен.
Обязательны `kind` и `sha256`; остальные поля необязательны. URL допускает HTTP(S).
Разметку делает оператор после проверки происхождения документа: название файла
и заявления внутри текста не дают официального статуса. При несовпадении хеша
статус становится `unknown`, ссылка из реестра не применяется. Изменение реестра
подхватывается при следующем запросе без пересчёта embeddings; изменение самого
PDF/TXT по-прежнему требует обновления индекса.

Из найденных кандидатов отчётность выбирается первой, альтернативный источник
сохраняется в контексте. Модель получает правила проверки сопоставимости периода,
единиц, организации, МСФО/РСБУ и периметра, выбора официального значения и указания
альтернативы с отдельной ссылкой. Неизвестная причина расхождения должна быть
названа неизвестной, разные методики нельзя автоматически считать противоречием.
При отсутствии официальной отчётности модель должна обозначить это ограничение.

Поиск не гарантирует, что найдены все версии показателя. Выявление расхождений и
их объяснение выполняет модель; это не детерминированная сверка всех чисел корпуса.
Проверка ссылок структурная, а не проверка достоверности каждого утверждения.
Реальное качество двух ролей и соблюдение правил источников нужно оценивать на
контрольных вопросах с подключённой моделью.

## Публикация на GitHub

Перед первым коммитом проверьте `git status --short` и `git diff --cached`.
`.gitignore` исключает корпус, `.env`, индексы, логи и машинные отчёты; `.env.example`
остаётся в репозитории. Исходные документы не добавляйте через `git add -f`.
Если секрет уже попадал в историю Git, одного `.gitignore` недостаточно.

После проверки файлов создайте пустой репозиторий на GitHub, затем:

```bash
git add .
git commit -m "Prepare RAG project for GitHub"
git branch -M main
git remote add origin <URL-вашего-репозитория>
git push -u origin main
```

Лицензия для распространения кода пока не выбрана владельцем проекта.
