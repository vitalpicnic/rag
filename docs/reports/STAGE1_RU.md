# Этап 1: метрики и контрольный набор

Инструменты реализованы. Фактическое качество облачных ответов, задержка API и стоимость ещё не измерены: индекс `faiss_indexes/Банкинг` отсутствует. Его создание относится к этапу 2 и требует подтверждения перехода. Модели, поиск `k=3`, промпт и размер истории не менялись.

## Результат

- `rag_metrics.py`: JSONL-журнал стадий `retrieval`, `generation`, `intent`, `image_generation`: время UTC, общий `request_id`, модель, длительность, статус, тип ошибки и usage. Ошибка записи журнала не скрывает ответ.
- `rag_pipeline.py`: сборка прежней цепочки с измерениями; используется из `rag_engine.py`. Ответ сохраняет `answer` и `sources`, дополнительно возвращает `request_id`.
- `bot.py`: intent и изображения связаны с запросом RAG. Обязательный intent пока сохранён для фиксации исходного поведения.
- `rag_eval_cases.json`: 30 вопросов, 7 категорий, эталонные ответы и физические страницы PDF. Стартовый набор на 6 документах нужно дополнить реальными вопросами пользователя; он не представляет все 47 PDF.
- `baseline_check.json`: 43 подтверждающих фрагмента проверены, сохранены хеши источников и корпуса. `baseline_status: not_run`, `index_ready: false`.

## Запуск

Из корня проекта, в окружении с зависимостями:

```powershell
python -m unittest discover -s tests -v
python scripts/evaluate_rag.py --check
```

В текущей среде рабочий Python: `C:/Users/picni/AppData/Local/Python/pythoncore-3.14-64/python.exe`; системный псевдоним `python` не запускается. Для тестов нужен `langchain-core==1.2.14`, для проверки PDF — `pypdf==6.7.1`; здесь используются локальные `.test_deps` и `.audit_deps`. Полная установка зависимостей приложения остановлена из-за длительного подбора версий. Тесты выполняют настоящую цепочку LangChain с локальными заменами модели и поиска, без сети. На Python 3.14 библиотека предупреждает об устаревшем `asyncio.iscoroutinefunction`.

После согласованного создания индекса и настройки API:

```powershell
python scripts/evaluate_rag.py --run --output reports/baseline_run_01.json
```

Этот режим обращается к облачным API. Без индекса останавливается до инициализации моделей, сам индекс не создаёт. Существующий отчёт не перезаписывает. Каждый кейс получает отдельную сессию; продолжения используют фиксированную историю из эталона. Результат содержит ответы, найденные тексты, эталоны и метрики. Журнал сохраняется рядом в `baseline_run_01.metrics.jsonl`. Прогон измеряет RAG; Telegram intent и изображения измеряются при работе бота.

## Оценка

`page_recall` — доля эталонных страниц среди найденных, без повторов. Старые абсолютные пути нормализуются по `data/тема/файл`, страницы retriever переводятся из нумерации с нуля в нумерацию с единицы. Совпадение страницы не гарантирует попадания нужной строки в фрагмент: проверяйте сохранённый текст. Ошибки исполнения показаны отдельно и не включены в среднюю полноту. Вопросы без ответа не получают автоматическую положительную оценку.

В результатах вручную заполните `review.answer_correct`, `review.citations_support_answer`, для отказов — `review.correct_refusal` значениями `true`/`false`; пояснения — в `review.notes`. Проверяйте числа, единицы, даты, статус прогноза и подтверждение утверждений. Неоценённые поля остаются `null`.

```powershell
python scripts/evaluate_rag.py --summarize reports/baseline_run_01.json --output reports/baseline_reviewed_01.json
```

Сводка содержит ошибки, среднюю полноту страниц, точность среди вручную оценённых ответов, число оценок и p50/p95 времени выполнения кейса.

## Ограничения

Журнал по умолчанию: `logs/rag_metrics.jsonl`; переопределение — `RAG_METRICS_PATH`. Новый журнал не содержит вопросов, ответов, ключей, пользовательских ID и текста исключений. Существующие логи приложения не менялись. Блокировка записи рассчитана на потоки одного процесса; разным процессам нужны разные файлы. Ротация пока отсутствует.

`output_tokens` включает thinking, а `thinking_tokens` — его часть; повторно прибавлять её нельзя. `cache_read_tokens` — часть входа. Неизвестные значения остаются `null`, включая полный выход при неполном Google usage. `application_calls: 1` означает вызов приложения; `internal_retry_count: null` — внутренние повторы SDK не наблюдаются. Новый вопрос получает новый ID.

Время retrieval включает embedding вопроса, но его токены retriever не раскрывает. Первоначальная индексация не измеряется. Сумма известных токенов генерации не равна полному счёту API: нужны актуальные тарифы и учёт неизвестных расходов. Облачные модели и индексация на этом этапе не запускались.

Следующее согласование: индекс и manifest на этапе 2, затем облачный baseline до оптимизаций этапа 3.
