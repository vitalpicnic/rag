# Этап 2: сборка и проверка индекса

Реализованы отдельная команда сборки и проверка готового индекса. Облачный индекс «Банкинг» пока не создан: требуется заполнить `GOOGLE_API_KEY` в `.env`. Локальная проверка всех 47 PDF дала 1 260 страниц и 3 828 фрагментов; документов без фрагментов нет. Актуальные подробности и хеши — в `index_preparation_verified.json`. Это отчёт подготовки, не готовый векторный индекс. Предыдущий `index_preparation.json` оставлен как история до исправления порядка файлов Windows/Linux.

## Настройки окружения

Общий `.env.example` находится в корне проекта. Отдельные файлы для Telegram, CLI, Streamlit и индексации не нужны. Если `.env` ещё нет, скопируйте пример:

```powershell
Copy-Item .env.example .env
```

Заполните `GOOGLE_API_KEY` для индексации и RAG. Для Telegram дополнительно нужны `TELEGRAM_BOT_TOKEN` и, при необходимости, `TELEGRAM_ADMIN_IDS` через запятую. Последний параметр разрешает административные команды, но не ограничивает доступ пользователей к боту. `RAG_METRICS_PATH` необязателен. Пустое значение оставляет стандартный путь журнала. Секретные `.env` исключены из Git, пример сохранён без секретов. Код бота теперь читает эти настройки из окружения.

## Команды

Выполняйте из корня проекта в Python-окружении с зависимостями:

```powershell
# Проверка извлечения и нарезки без API:
python build_index.py --topic Банкинг --inspect

# Сборка с Google embedding API:
python build_index.py --topic Банкинг --build

# Проверка опубликованного индекса без API:
python build_index.py --topic Банкинг --check

# Оценка после успешной сборки (вызывает облачные модели):
python scripts/evaluate_rag.py --run --output reports/baseline_run_01.json

# CLI с явным выбором темы:
python main.py --topic Банкинг
```

Для сохранения нового отчёта добавьте `--output путь.json`. Существующие отчёты не перезаписываются. В текущем окружении рабочий интерпретатор — `C:/Users/picni/AppData/Local/Python/pythoncore-3.14-64/python.exe`, системный псевдоним `python` не работает. Локальные зависимости проверки расположены в `.runtime_deps` и `.test_deps`; при ручном запуске здесь можно задать:

```powershell
$env:PYTHONPATH = "$PWD\.runtime_deps;$PWD\.test_deps"
```

Это окружение проверок индекса, не полная установка Telegram/Streamlit. Зависимости пользовательских интерфейсов устанавливаются отдельно из `requirements.txt`; известное отсутствие matplotlib в этом списке остаётся задачей этапа 3.

На Python 3.14 библиотеки предупреждают о совместимости Pydantic V1 и устаревших API. Локальные тесты и импорт RAG проходят; полный запуск интерфейсов и реальные запросы к Google этим не подтверждены.

## Что гарантирует сборка

`rag_index.py` учитывает PDF и TXT внутри папки темы, включая подпапки. Manifest содержит хеши и размеры файлов, стабильные идентификаторы источников, embedding-модель и размерность, настройки нарезки и извлечения, версии библиотек, число документов, страниц и фрагментов. На диске источники имеют относительные пути; после загрузки они разрешаются относительно текущего проекта для скачивания PDF. Даты публикации и среза данных автоматически не выводятся: это последующая доработка метаданных.

Версии хранятся в `faiss_indexes/<тема>/versions/<id>/`. Каждая содержит `index.faiss`, `index.pkl`, `chunks.jsonl` и `manifest.json`. Указатель `current.json` переключается атомарной заменой файла только после сохранения, повторной загрузки индекса и повторной проверки корпуса. Ошибка embedding, записи или смена документов во время сборки не заменяют прежний указатель.

Добавление, изменение и удаление документов требуют полного перестроения. Повторная сборка неизменённого корпуса возвращает `unchanged`, без embedding-вызовов. Размерность и соответствие векторов фрагментам проверяются; несовместимые настройки и повреждённые файлы блокируют загрузку. Старые индексы без manifest автоматически не принимаются и не удаляются.

Бот больше не строит индекс внутри обработчика. Перед каждым поиском проверяется актуальность; новую опубликованную версию он подхватывает без перезапуска. Если корпус изменён, а индекс ещё не обновлён, запрос отклоняется вместо ответа по устаревшему индексу. Проверка читает и хеширует файлы, поэтому добавляет дисковую работу к каждому поиску; её время входит в метрику retrieval.

Параллельные сборки защищены `build.lock`. После аварийного завершения файл блокировки может остаться: перед ручным удалением проверьте, что указанный в нём процесс завершён. Предыдущие и незавершённые версии автоматически не удаляются. Хеши обнаруживают повреждения, но не заменяют доверие к локальным файлам pickle; не подменяйте артефакты файлами из недоверенных источников.

## Проверки и следующий шаг

Тесты используют настоящий FAISS и локальные тестовые embeddings только во временных папках. Проверяются изменения корпуса, перенос проекта, смена версии, ошибки публикации и embedding, повреждения, размерность и блокировка сборки. Рабочего индекса с тестовыми векторами не создаётся.

По последующему указанию пользователя работа продолжена без реальных ключей, переход к этапу 3 подтверждён. Полная офлайн-проверка сборки выполнена во временном индексе, подготовленные фрагменты сохранены; рабочий Google-индекс и облачный baseline отложены. Актуальные результаты и команды приведены в `STAGE3_RU.md` и `offline_index_verification.json`.
