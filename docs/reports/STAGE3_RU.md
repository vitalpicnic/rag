# Этап 3: один вызов модели и устойчивый Telegram

Работа выполнена без реальных ключей Google и Telegram. Пройден полный локальный цикл FAISS для 47 PDF и 3 828 фрагментов: сборка, сохранение, загрузка, проверка источников и повторная сборка без изменений. Отчёт: `offline_index_verification.json`. Тестовые embeddings не являются семантическими и несовместимы с Google; временный индекс удалён. Качество поиска таким тестом не измеряется.

Настоящие тексты сохранены в `prepared_corpora/Банкинг/<fingerprint>/chunks.jsonl` вместе с manifest. `build_index.py --prepare` повторяет эту подготовку без ключей. Будущая команда `--build` использует подготовленные фрагменты после проверки хеша и настроек. Рабочий Google-индекс не опубликован. Обнаруженная при проверке ошибка FAISS на Windows с кириллицей в пути исправлена: двоичные данные сохраняются и загружаются через Python, без передачи русского пути в C++ файловый API.

## Изменения в обработке запросов

- Удалены обязательный intent-классификатор и вызов Imagen. Обычный ответ или обзор выполняет один вызов LLM на уровне приложения. При временной ошибке SDK допускает не более двух попыток, включая первоначальную; это не два обязательных вызова на каждый вопрос.
- Добавлены режимы «Текст», «Обзор», «График» и отдельная справка. Справка, меню, переключение режима и скачивание источника не вызывают модель.
- Текст ограничен 600 выходными токенами, обзор — 1 200, thinking выключен. История ограничена бюджетом примерно 800 токенов и в памяти, и в промпте. Оценка истории локальная: UTF-8-байты / 4 плюс служебный запас; это не точный tokenizer Gemini. Сохраняются последние реплики, слишком длинная последняя пара сокращается. Вопросы длиннее 8 000 символов отклоняются до embedding.
- Загрузка индекса и синхронный RAG выполняются в одном фоновом worker. Очередь вмещает до 8 ожидающих задач. Справка и меню не ждут завершения модели.
- Общий таймаут ожидания — 60 секунд, включая очередь. Запрос генерации имеет таймаут 30 секунд, embedding — 15 секунд; максимум две SDK-попытки. После пользовательского таймаута worker ждёт фактического завершения уже начатого синхронного вызова, не запускает второй одновременно и не отправляет поздний ответ. Просроченные задачи, которые ещё не начались, пропускаются.
- Очистка чата, смена темы и таймаут меняют идентификатор сессии. Поздние результаты старой сессии не попадают в новую; история разделена по чату и пользователю.
- Ответы экранируются как HTML и разбиваются без разрыва HTML-сущностей и символов emoji. Markdown выводится как обычный текст. Ссылки на скачивание привязаны к пользователю и текущему ответу.
- `TELEGRAM_ALLOWED_USER_IDS` позволяет ограничить доступ к личному боту. Пустое значение сохраняет открытый доступ; настройка описана в `.env.example`.

## Что осталось за пределами этапа

Режим графика пока возвращает текст и сообщает об отсутствии подключённых проверенных таблиц. Извлечение чисел из ответа модели удалено; проверенные показатели и локальные графики относятся к этапу 5. Зависимость от matplotlib при импорте бота устранена вместе со старой веткой графиков.

«Обзор» меняет инструкции и бюджет ответа, но ещё использует прежний поиск `k=3`. Разнообразие источников, даты, достоверность цитат и контекст продолжений относятся к этапу 4. Реальные качество, квоты, задержки API и экономия не измерялись; сравнение с облачным baseline без ключей не выполнено.

## Проверка без ключей

В текущей среде PowerShell:

```powershell
$ragPython = 'C:/Users/picni/AppData/Local/Python/pythoncore-3.14-64/python.exe'
$env:PYTHONPATH = "$PWD\.runtime_deps;$PWD\.test_deps"
& $ragPython bot.py --check
& $ragPython -m unittest discover -s tests -v
& $ragPython build_index.py --topic Банкинг --prepare
```

`bot.py --check` проверяет импорт и сообщает локальную готовность, не создавая Telegram-клиент и не вызывая API. Для настоящего polling отдельный запуск без `--check` требует заполненного `.env`; в этой работе он не выполнялся.

Тесты проверяют реальные объекты FAISS, цепочку LangChain и маршрутизацию aiogram; внешние транспорт и ответы модели заменены локальными тестовыми объектами. Есть предупреждения библиотек о Pydantic V1 и устаревших API на Python 3.14; успешные локальные тесты не гарантируют совместимость всех функций библиотек.

Следующее согласование: этап 4 — метаданные, достоверность поиска, несколько источников для обзоров и корректный отказ при недостатке данных.
