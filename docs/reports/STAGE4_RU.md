# Этап 4: контекст, источники и отказ

Реализована и проверена офлайн-часть этапа. Google API и Telegram не вызывались. Калибровка порога релевантности и проверка правильности ответов реальной модели остаются открытыми до появления рабочего Google-индекса.

## Изменения

- Название и издатель извлекаются из имени файла с указанием происхождения. Поля `as_of` и `updated_at` извлекаются отдельно по явно подписанным датам с сохранением физической страницы подтверждения. Неоднозначные и неверные даты пропускаются. Дата публикации и период показателя не угадываются.
- Версия конвейера индексации повышена до 3, версия метаданных — 1. Старые подготовленные фрагменты не переиспользуются как новая версия.
- Для продолжений вроде «А на начало того же года?» поиск учитывает последние три доступных вопроса пользователя, максимум 2 400 символов. Ответы ассистента не включаются. Текущий вопрос помечается приоритетным при смене организации или периода. Это ограниченная эвристика, а не полное разрешение сущностей.
- Для фактов выбираются до 3 фрагментов из 12 кандидатов. Для обзоров — до 6 из 24, максимум 2 из одного документа. Повторы удаляются. Разнообразие внутри выборки не гарантирует полноту архива.
- Контекст ограничен 14 000 символами, отдельный фрагмент — 2 000. Блоки `[S1]` содержат источник и физическую страницу. Подписанная дата включается только для страницы, где она подтверждена.
- Промпт требует проверять организацию, период, единицы, различать факт и прогноз, сопровождать факты ссылками. История не считается доказательством, инструкции внутри документов должны игнорироваться.
- При пустой выборке модель не вызывается. Ответ с `INSUFFICIENT_EVIDENCE`, без ссылок или с недопустимым номером источника заменяется сообщением о недостатке подтверждений в найденных материалах. Повторного вызова модели нет. Приложение добавляет расшифровку ссылок: файл и страница.
- Проверка ссылок структурная: наличие `[S1]` не доказывает, что источник подтверждает утверждение. Это отражено статусом `cited_unverified`.
- Оценочный запуск передаёт режим обзора и сохраняет метаданные, расстояние squared L2, embedding-модель, fingerprint индекса и статус подтверждений. Удалено дублирующее определение `run_cases`. Поле `retrieval_calibrated=false` явно показывает отсутствие настроенного порога.

## Проверки

- 57 тестов: цепочка LangChain, история, отказ без генерации, ссылки, метаданные, разнообразие, бюджет контекста, режимы FAISS, оценочный отчёт и существующие проверки бота/индекса.
- Подготовлены 47 PDF, 3 828 фрагментов. Название добавлено во все фрагменты. Проверены все 30 ожидаемых ссылок на страницы из контрольного набора. Это проверка наличия и форматирования страниц, а не измерение retrieval recall.
- На реальных PDF подтверждены `as_of=2026-03-06` у мартовского выпуска, `as_of=2026-01-30` у февральского (обе стр. 2), `updated_at=2026-02-06` у СБП (стр. 3). Ложный заголовок «декабрь 2021» не принят за дату выпуска.
- `bot.py --check`: импорт успешен; ключи отсутствуют, рабочий индекс не готов.
- [Полная проверка временного FAISS](../../reports/stage4_offline_index_verification.json): сборка, сохранение, загрузка, повторная сборка без изменений. 47 документов, 3 828 векторов, 0 API-вызовов; временный индекс удалён. SHA-векторы используются только для технической проверки и не являются семантическими.

Fingerprint подготовки: `3635484be38c2d58f06bbb03981b43debacb9c8dfb84012511781969d1ee47a6`.

## Оставшаяся проверка с реальным индексом

Запустить контрольные вопросы, вручную проверить факты и подтверждения, отдельно оценить продолжения, обзоры и отказы. Для настройки порога нужны размеченные положительные и отрицательные примеры расстояний конкретной embedding-модели и независимая проверочная выборка. Два отрицательных вопроса текущего набора недостаточны для надёжной калибровки. Произвольный порог на SHA-векторах не используется. Качество поиска, точность отказов и задержки Google пока не измерены.
