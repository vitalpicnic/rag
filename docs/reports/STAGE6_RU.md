# Этап 6: сравнение моделей, расходы и подготовка запуска

Выполнена офлайн-часть. Облачный benchmark, выбор победителя по качеству и публикация сервиса не выполнялись. Реального Google-индекса и ключей нет. Текущая модель по умолчанию сохранена.

## Изменения

- `RAG_MODEL` в `.env` выбирает `gemini-2.5-flash`, `gemini-2.5-flash-lite` или `gemini-3.1-flash-lite`. Неизвестное имя отклоняется. Генерационная модель не меняет embedding-пространство и не требует пересборки индекса. Для 2.5 задан `thinking_budget=0`, для 3.1 — `thinking_level=low`; настройки не смешиваются.
- Оценочный CLI принимает `--model`, записывает выбранную конфигурацию, хеши вопросов, кода и индекса. Метрики генерации содержат фактическое имя выбранной модели.
- `scripts/compare_models.py` без аргументов рассчитывает сценарии. С JSON-отчётами сравнивает качество после ручной проверки, задержки и оценочную стоимость. Различающиеся вопросы, код, индекс или порядок кейсов отклоняются. Автоматического победителя нет.
- Thinking уже входит в output tokens и не прибавляется повторно. Стоимость по журналам оценивается без скидок за кэш. Неизвестный расход не считается нулём. Ошибки и скрытые повторы SDK могут сделать оценку неполной; это не счёт провайдера.
- `run.ps1` запускает проверку, тесты, подготовку текста, таблицы, расчёт стоимости либо бот. По умолчанию выполняется только `Check`; скрипт не строит облачный индекс. Рабочая папка и временные переменные окружения восстанавливаются.
- `requirements-bot.txt` выделяет прямые зависимости бота, индексации, графиков и CLI. Это не полный lockfile: транзитивные зависимости разрешает pip. Исходный requirements.txt сохранён для остальных интерфейсов.

## Сценарий расходов

Предположение: 2 000 входных и 600 выходных токенов на запрос, 30 дней, Standard text pricing. Это не фактический размер контекста проекта и не результат замера. Обзор и thinking могут увеличить расход.

| Модель | Вход / выход, USD за 1 млн токенов | 300 запросов | 1 500 запросов |
|---|---:|---:|---:|
| Gemini 2.5 Flash | 0,30 / 2,50 | $0,63 | $3,15 |
| Gemini 2.5 Flash-Lite | 0,10 / 0,40 | $0,132 | $0,66 |
| Gemini 3.1 Flash-Lite | 0,25 / 1,50 | $0,42 | $2,10 |

Тарифы проверены 20.09.2026 по [Google pricing](https://ai.google.dev/gemini-api/docs/pricing). Не включены embeddings, индексация, скрытые повторы, налоги и размещение. Бесплатная квота зависит от аккаунта; нулевая стоимость не гарантируется. Машиночитаемый расчёт: [stage6_cost_scenarios.json](../../reports/stage6_cost_scenarios.json).

Мой предварительный кандидат для экономии — 2.5 Flash-Lite при доступности аккаунту и сохранении качества. 3.1 Flash-Lite подготовлен как дополнительный кандидат, не автоматическая замена. Перед запуском проверить [жизненный цикл моделей](https://ai.google.dev/gemini-api/docs/deprecations) и фактическую доступность ключу. Локальная инициализация SDK не доказывает доступность API.

## Запуск на Windows

В имеющейся среде:

```powershell
$ragPython = 'C:/Users/picni/AppData/Local/Python/pythoncore-3.14-64/python.exe'
$env:PYTHONPATH = "$PWD\.runtime_deps;$PWD\.test_deps"
& $ragPython bot.py --check
& $ragPython -m unittest discover -s tests -q
& $ragPython scripts/compare_models.py
```

Локальный launcher также проверен с `-Python` и `-UseLocalDependencies`. В этой Windows запуск ps1 запрещён политикой: для проверки использовалось разрешение только на один процесс, без изменения постоянной политики. Прямые команды Python выше не требуют запуска ps1.

Для отдельного окружения:

```powershell
& $ragPython -m venv .venv
& ./.venv/Scripts/python.exe -m pip install -r requirements-bot.txt
& ./.venv/Scripts/python.exe build_tables.py
& ./.venv/Scripts/python.exe bot.py --check
```

Команды установки здесь приведены для последующего запуска; новое venv в этой работе не разворачивалось. `.runtime_deps` — локальное тестовое окружение, а не образ для сервера. Проверки выполнены на Python 3.14; остаются предупреждения совместимости Pydantic V1. Другой Python и Linux/VPS требуют отдельной проверки.

Скопировать `.env.example` в `.env`, только если `.env` ещё нет. Для Telegram-графиков заполнить TELEGRAM_BOT_TOKEN; для текстового RAG дополнительно GOOGLE_API_KEY. Для личного запуска указать TELEGRAM_ALLOWED_USER_IDS. Значения ключей в отчёты не выводятся.

После настройки реальных ключей (эти команды вызывают API):

```powershell
& ./.venv/Scripts/python.exe build_index.py --topic Банкинг --build
& ./.venv/Scripts/python.exe bot.py
```

Запускать один экземпляр polling-бота. Для переноса сохранить исходные PDF, код, .env отдельно, версионированный индекс и его current.json. SQLite можно пересобрать. Для отката модели вернуть RAG_MODEL; для отката индекса использовать сохранённую проверенную версию вместе с соответствующим корпусом. Автозапуск, VPS и внешняя публикация в этом этапе не настраивались.

## Реальное сравнение после настройки ключей

```powershell
& ./.venv/Scripts/python.exe scripts/evaluate_rag.py --run --model gemini-2.5-flash --output reports/eval_flash.json
& ./.venv/Scripts/python.exe scripts/evaluate_rag.py --run --model gemini-2.5-flash-lite --output reports/eval_lite.json
& ./.venv/Scripts/python.exe scripts/evaluate_rag.py --run --model gemini-3.1-flash-lite --output reports/eval_31.json
```

Для повторений использовать новые имена отчётов. В каждом результате заполнить `review`: правильность ответа, подтверждение источниками и корректность решения отвечать/отказывать. Затем:

```powershell
& ./.venv/Scripts/python.exe scripts/compare_models.py reports/eval_flash.json reports/eval_lite.json reports/eval_31.json --output reports/model_comparison.json
```

Критерий перехода: отсутствие новых ошибочных чисел/периодов, неподтверждённых ответов и пропущенных отказов; сопоставимые результаты по каждой категории, затем стоимость и p95. Повторить сравнение для оценки разброса задержек. Тридцать вопросов по шести документам недостаточны для гарантии качества всего корпуса. Калибровка порога отказа этапа 4 требует отдельной размеченной выборки.

## Проверки

65 тестов проходят. Три профиля создают локальные объекты SDK с фиктивным ключом, без запросов. [Офлайн-проверка](../../reports/stage6_preflight.json): 30 кейсов, 43 подтверждения в PDF, ошибок нет, облачная оценка `not_run`. Таблицы готовы: 10 наблюдений. Рабочий RAG-индекс не готов, ключи отсутствуют.

`pip install --dry-run --ignore-installed -r requirements-bot.txt` завершился успешно. [Отчёт разрешения зависимостей](../../reports/stage6_dependencies.json) относится к текущей Windows/Python 3.14; это проверка совместимости ограничений пакетов, не проверка свежей установленной среды.

Стоимость, фактические задержки API, семантическое качество и потребление памяти под рабочей нагрузкой ещё не измерены. Этап подготовил инструменты и процедуру, но не завершил облачную приёмку.
